# 00 — Overview

## What this is

A personal web app that makes the mechanical substrate of playing piano — key/chord fluency, staff reading, rhythm, keyboard topography — automatic, in 10–20 focused minutes a day, so that learning new pieces gets faster and motivation compounds.

**The thesis flywheel:** fluency → new pieces come together faster → starting a piece stops being a grind → songs actually get finished → you keep sitting down at the piano.

**The differentiators** (verified unserved by the 2026-08 market survey): true SRS on musical micro-skills answered on a MIDI keyboard; mistake-pattern diagnosis; generation conditioned on weaknesses; an adaptive, quota-free practice surface (the strength map + weakest-first filling).

## Posture

Personal tool first, and **the project is open source under MIT**, with LLC productization still an option later. Practical consequences: the bundle stays permissive-license-only (a GPL dependency would force copyleft on our license choice — see 10-ARCHITECTURE), every shipped asset must be redistribution-clean (OFL fonts, MIT/ISC icon sets, CC-BY samples with attribution), personal content never enters the repo, and secrets hygiene is repo-public-grade from day one. `userId` on every table from day 1, auth deferred but schema-ready. Stripe/multi-user/marketing: parked entirely.

## The learning model in one paragraph

Three engines because piano fluency is three learning problems: **(A)** FSRS-scheduled retrieval drills answered on the keyboard (keys, chords, intervals — true SRS territory); **(B)** FSRS on reading-pattern *classes* whose concrete instances are freshly generated every rep (schedule the class, never the card — reading material must stay novel); **(C)** generated sight-reading passages under an adaptive per-axis difficulty staircase (not SRS — you never see a passage twice). Layer **(D)**, prescriptions, turns logged error events from all three into targeted remedial work.

## Glossary

| Term | Meaning |
|---|---|
| **Atom / item** | The smallest schedulable skill unit: a typed, parameterized config (e.g., `chord.play {root: Ab, quality: maj7, inversion: 1, hand: RH, cue: staff}`) |
| **Card** | An atom plus its per-user FSRS state |
| **Class** | An engine-B atom whose reps render fresh generated **instances** (the class is scheduled; instances are never repeated) |
| **Engines A · B · C · D** | The four learning machines: **A** = FSRS retrieval drills on atoms, answered at the keyboard (04) · **B** = FSRS on pattern *classes* with instances generated fresh each rep (02 §1, 04 §5) · **C** = generated passages/eyes-ahead reads steered by the per-axis staircase — never repeated, not SRS (05, 06) · **D** = the prescription layer reading error evidence from all three (09) |
| **Tier** | A difficulty stage *within* an atom family, written with T-numbers (e.g., T1 blocked → T2 inversions → T3 hands-together). Ladders describe **execution/content progression only** — knowledge (choice) variants are tierless flat atoms |
| **Rank · subrank** | An axis's position on 05's ladder, written like a game ranking: ranks **F→E→D→C→B→A→S→SS→SSS** × subranks `--` `-` `+` `++` `+++` (e.g., `B+`; `C--` = just entered C). Stored as ordinals. No relation to family tiers |
| **League** | A rating display bucket (07): six 300-point leagues Bronze→Master with divisions III–I, headlining the numeric rating ("Gold II · 840"). A *ratings* vocabulary — ranks say how hard the material is; leagues say how far you've climbed |
| **Fluency gate** | A tier whose only change is the clock: the latency window for a Good rating derives from an external tempo anchor (RCM technique requirements — e.g., ~one beat at ♩=66 for solid triads) instead of the generous learning window. Accuracy rules are unchanged |
| **Cue modality** | How the prompt is presented: name/symbol, staff notation, key signature, (audio — later) |
| **Answer modality** | How you respond: MIDI-play, choice-tap (recognition), rhythm-tap |
| **Mode** | Grading context: **Rehearsal** (accuracy-first, self-paced tolerance) vs **Performance** (locked pulse, continuity counts) — see 03-GRADING |
| **Axis** | An independently-tracked difficulty dimension (keys, rhythm, texture, range, reading span) |
| **Drill scope** | Per-family visibility config (02 §5): individual-value toggles choosing what is *drilled*; excluded atoms hide and decay silently — never suspended |
| **Admission / frontier** | The order new atoms enter (each family's tier ladder × key wave) and the boundary frontier-on-pull walks as practice thins an area's weak pool (05 §2) |
| **Subsumption / derived review** | HT ⊐ RH/LH: a clean embedded sub-performance writes an improvement-only review flagged `derived` to the subsumed atom (02 §3) |
| **Strength / upkeep** | An atom's modeled retrievability, decaying continuously (FSRS) — the mirror of the brain. "Due" = strength crossing the retention target, surfaced on the strength map as weak counts and per-drill pips, never as debt |
| **Template / block** | A user-authored practice plan: a named sequence of blocks (area selectors, open-ended or duration/count-boxed) that the block-filler serves weakest-first. Practice outside any template counts identically (08) |
| **Diagnosis / prescription** | Aggregated error evidence → concrete remedial drill spec (09-PRESCRIPTIONS) |
| **Benchmark** | The monthly SASR-style staircase test that re-anchors the rating sources (07-RATINGS — it never publishes a competing number) |
| **Knowledge-only mode** | Practice with no instrument present: recognition/choice exercises only — a filter on the strength map, not a separate app mode |
